Introduction

Robot Framework library for deterministic time control.

TimeTravel uses time-machine to manipulate Python-level time APIs in the current process and exposes readable keywords for freezing, traveling, advancing, rewinding, and timezone-aware datetime interpretation.

This library does not change remote services, databases, browsers, or other processes.

By default the library auto-resets simulated time at the end of every test so frozen clocks do not leak between tests. Pass auto_reset=${False} to disable that behavior and manage cleanup yourself with Reset Time.

Examples:

Advance To Next Weekday

Source:L333

Arguments

weekday : str required

Target weekday name or abbreviation.

keep_time : bool default: True

Keep the current time-of-day when True.

Returns

str

The simulated datetime as an ISO-8601 string.

Documentation

Advance to the next weekday, never staying on today.

weekday accepts names like Monday or abbreviations like Mon. When keep_time is true (default), the current time-of-day is kept. When false, the destination is midnight in the interpretation timezone.

Example

Set Timezone

Source:L24

Arguments

timezone : str required

IANA timezone name.

Returns

str

The configured timezone name.

Documentation

Configure the timezone used to interpret naive datetime inputs.

Accepts IANA identifiers such as UTC, Asia/Kolkata, or America/New_York.

This does not by itself claim to change the operating-system timezone. When freezing or traveling to a timezone-aware instant with a named zone, the time-machine backend may temporarily set process TZ while the clock is active.

Example

*** Test Cases ***
Naive Instant In Kolkata
    [Teardown]    Reset Time
    Set Timezone    Asia/Kolkata
    Freeze Time    2026-01-01T05:30:00
    ${now}=    Get Current Simulated Time
    Should Start With    ${now}    2026-01-01T05:30:00+05:30
    ${tz}=    Get Current Timezone
    Should Be Equal    ${tz}    Asia/Kolkata
